PART A — How to post a new report (public, no login)

Screen: /report/new (top-right + Report on every page). Works in any city. Nothing here needs an account.

A1. Open the form

Click + Report. You see Report an accessibility obstacle with the note: A new report starts as Unverified — a reviewer verifies it later.

A2. Fill the fields top to bottom

1. Title (required, max 200). Name the place so a stranger can find it. Good: Zindabazar crossing — rickshaw stand on the ramp. Bad: blocked. Under the box the error reads Title is required if you leave it empty.

2. Description (optional) (max 2000). What blocks it, how much width is left, when you saw it. Example: Two slabs lifted at the joint by the tree, front wheels catch. Seen 4 Nov 2pm. After photo shows repaved.

3. Obstacle type (dropdown, default Unknown): BlockedSidewalk · BrokenSurface · MissingOrBlockedRamp · StairsOrStep · ConstructionBarrier · Other · Unknown. Pick the closest visible thing. Broken slabs = BrokenSurface. Scooters across path = BlockedSidewalk. Unsure = leave Unknown.

4. Severity (default Unknown): Unknown · Low · Medium · High. Lip across walking line that can tip a chair = High. Cosmetic crack = Low.

A3. Location — three ways, pick one

Option 1 — Use my location (button). Browser GPS fills Latitude/Longitude and shows e.g. Location filled from your browser (accuracy about 12 m). Check it before submitting. Over 50 m it adds Accuracy is low (>50m) — drag the map pin to fine-tune; over 100 m Very low — please verify on map. If permission was denied: Location permission was denied. Enter coordinates manually.

Option 2 — Pick on map (button toggles to Hide map picker). An embedded map opens; click to drop the pin, drag to adjust. It writes 6-decimal coordinates and the note Picked on map — lat, lon. Drag the marker or click again to adjust.

Option 3 — type numbers directly into Latitude (-90..90) / Longitude (-180..180). Wrong range gives a field error on submit.

The page reminds you: Coordinates you enter are a claim about where the obstacle is, not a verified fact.

A4. What did you actually see? (the honesty block)

Fieldset What did you actually see? (optional — Unknown is honest): Stairs or a step here? Unknown/Yes/No · Ramp here? Unknown/Yes/No · Surface Unknown/Smooth/Uneven/Broken. Only set what you observed yourself. A wrong No is worse than an honest Unknown — the route card later reads Stairs/ramp/surface not measured here (unknown, not estimated).

A5. Consent + submit

Tick the consent box (required — my own photo, no faces/plates, storage per retention policy; removal via maintainer request, no delete button yet). Press Create report (shows Saving…). Offline? It says Saved locally — will send when online and queues it. Success takes you straight to the new report page, status Unverified.

A6. Add photo + run Meta AI (same report page, Photo evidence)

Under Photo evidence click the drop zone (Choose a photo or drop it here), optionally set When was this photo taken? (your claim; empty = upload time, and comparisons lose time-trust without it). Press Upload photo (progress bar shows percent). Each card then offers Run analysis (or Retry analysis after Analysis failed). Result card: Possible obstacle tag, AI confidence bar with percent + Low/Medium/High verdict, Obstruction share (sam-3.1, in-photo percent or not measured), Visible evidence bullets, Limitations, provider badge Live Meta AI — Meta · muse-spark-1.3 vs red Demo/mock — not real AI, and yellow Human review required. Photos paginate 5 per page.

A7. Compare + feedback + edit

Evidence explorer — compare over time: pick Earlier photo + Later photo, press Compare photos (needs Completed analysis on both). Outcome card: LikelyStillPresent · NotObservedInNewImage · ConflictingEvidence · Inconclusive with explanation + reviewer note box. Quick feedback: four buttons Still visible / Not in new photo / Information wrong or old / Not sure + optional note (max 2000) — Thanks — recorded. It does not auto-change verification. Edit: Edit report link opens Title/Description/Obstacle type/Severity + Save changes (location is intentionally not editable).

PART B — How to plan a route (public, no login)

Screen: /routes → Plan a route (Compare walking routes by what is actually known… No route is labelled safe just because it has no reports). Backend: POST /api/routes/recommend → real OSRM foot geometry; provider failure = 502 and No route could be built, never an invented line.

B1. Set origin and destination (three ways each)

Boxes show Latitude / Longitude placeholders (Lat 24.9116 / Lon 91.8498). Fill by: (1) typing numbers, (2) address search — origin box placeholder Search address — e.g. Zindabazar, Dhaka or Market St, San Francisco, destination Amberkhana, Dhaka or Ferry Building, San Francisco — type + Enter (Nominatim), (3) map: press Click origin on map / Click destination on map (active button reads Clicking sets origin/destination…), then click the map. The mini form Plan a new route button collapses to keep the map tall on mobile.

B2. Preferences (saved on this device)

Checkboxes with exact labels: Avoid stairs (hard rule) · Prefer verified evidence · Avoid stale evidence (>30d) · Prefer shortest. Stored in localStorage pathlens.routePreferences; mirrored as pills under the map (Preferences: [Avoid stairs ON]… Saved on this device · never hides known obstacles · unknown stays unknown) and echoed per result as Preferences applied:. Honest line above Plan routes: Routes use a walking profile; that is not a validated wheelchair profile, so no route is ever labelled wheelchair-safe here.

B3. Press Plan routes and read the cards

Button Plan routes (busy: Planning…). Header: Candidate routes — From OSRM (foot profile), ranked by fewest known obstacles. Ranked first never means proven safe. Each card: Route N · X.XX km · N min + badges (Recommended / Blocked — see alternative below / Mostly unknown, Stale evidence on route, Confirmed stairs) + Show on map / Showing on map toggle + unknown bar (hatched Unknown X% — no nearby report, not proven clear vs solid Covered by nearby evidence) + Mostly unknown N% note over 50% + explanation bullets (e.g. 1 known obstacle within 50 m · evidence 12 d old — stale · covers about 23% of the visible walkway in its photo (SAM 3.1; share of photo, not metres)) + Known obstacles table (title link, type chip, ~N m from route, evidence date · N d old — stale, Certain (human-verified) / Uncertain (camera / not verified), observed stairs/ramp/surface or not measured here (unknown, not estimated)). Coverage layer under the polyline is toggleable (Coverage: show / hide).

OSRM foot routing is not wheelchair-validated. No route is ever labelled wheelchair-safe. 400/empty responses mean Routing failed (400): try closer points… — adjust, never trust a missing line.

PART C — How a reviewer reviews (Reviewer login)

Screen: /reviewer → Reviewer dashboard (Human review turns a claim into something others can rely on… previous value is never erased). Sign in with the one-tap Reviewer card (reviewer@pathlens.local / Reviewer@123). The User card exists to prove 403; a User session sees Your session is not a reviewer session. Log in with a reviewer account. An Admin login also passes the queue.

C1. Work the queue top to bottom

Reports waiting for review (N) — every card: title link (Open →), chips (obstacle · Unverified · created date · Camera candidate / Possible duplicate of XXXXXXXX). Open the report, read photo + AI findings + timeline, come back, type a Review note (placeholder e.g. Verified on site today, ramp clear), press HumanVerified (green) / Disputed (ghost) / Rejected (red). Result line: Marked HumanVerified — audit recorded or Review failed (400/401/403): …. Decide each row — one shared note box is per-card state, not global.

Stale cameras (N) — No enabled camera is stale right now vs stale cards (provider · city · last success · error, red Stale, Do not treat this feed as current evidence). Read-only here; polling lives in /admin.

Comparisons waiting for review (N) — card: comparison → report link · Inconclusive · created, same three buttons + note.

Possible duplicates: two buttons per card — Confirm duplicate (now a pointer to the main report; nothing was deleted) / Reject duplicate (both reports stay independent). No suggestion = reviewer decides on the report itself.

C2. Check the audit + log out

Recent audit trail (N) — rows: time, entity · action, from → to + id prefix, note. Empty: No review actions recorded yet. Rule to remember: a review is stored beside the AI outcome (effective outcome changes, original never overwritten). Log out from the session bar pill when done.

PART D — How an admin sets cameras, analytics, reputation (Admin login only)

Screen: /admin → City operations (Camera registry, city analytics and reporter reputation… an admin never edits a verdict from here). Sign in with the one-tap Admin card (admin@pathlens.local / Admin@123). Reviewer/User sessions see the yellow box signed in as Reviewer/User… Admin-only — the API answers 403… Sign out and use the Admin demo account.

D1. Register a camera (all fields + what fails)

Panel Camera registry → form Register a new camera source. Fields in order: Provider (dropdown Datumfeed · FiveOneOneSfBay · SfMta · Caltrans · GenericPublicFeed · NycDot), External ID (required, e.g. SF_001), Label (required, e.g. Market St & 5th — SF Demo), City (any text, e.g. San Francisco), Latitude / Longitude (defaults 37.7749 / -122.4194), Feed image URL (absolute http(s), e.g. https://datumfeed.com/api/cameras/SF_001/image), Permission / terms note (e.g. Datumfeed Developer Agreement 2026-10-30, powered by Datumfeed, SF demo), Cadence (seconds) (min 60). Press Register camera. Failures print inline: Failed (400): …permission/terms note… (enable without note is refused by design), bad URL, bad coords, bad provider. Success: Camera registered successfully.

D2. Enable, poll, import, stale (the live loop)

Table columns Camera / Feed / Status / Actions. Row: label + provider · city, feed URL + last success, pill Active/Inactive + No permission note — cannot enable / lastError. Buttons: Edit (feed URL + permission note, Save/Cancel), Enable/Disable (Enabled/Disabled.), Poll now (Poll 200: Changed / Unchanged / CandidateCreated / Failed: reason). Header helpers: Enable all eligible, Poll all active, Import N active Datumfeed cameras (city + limit inputs; needs server key or Import failed (400): Datumfeed API key not configured). Footer truth: Enable a camera, then Poll now… square C marker — evidence, never a verdict. Mechanics to quote on camera: unchanged SHA-256 → nothing; changed → CameraFeed evidence on nearest report ≤100 m else auto CameraDetected candidate (Unknown/Unverified) into the Meta AI queue; dark/blurry/changed-view frames stored but flagged no AI analysis will run; daily budget + 60 s cadence enforced; live auto-polling is OFF on the demo so trigger manually. Stale = no success in 10 min — flagged, never trusted.

D3. City analytics + reputation (read-only)

City analytics — all cities (live GET /api/admin/stats): Total reports · Human-verified % · Stale >30d % · Unknown share (map) · Feedback wrong/stale of total · Reports per day last 7 chart (+ Run ./scripts/seed-sf.ps1 to populate when empty). Reputation: Bronze 1+ / Silver 3+ / Gold 5+ verified reports — empty on the demo (seeded reports have no author), shown as empty, never invented. Footer: Feedback is grouped weekly… a tap never changes verification.

2. Public user — no account needed

2.1 Accessibility map (/map)

1Open Accessibility map. Pan or zoom — reports reload for the area you look at. A place with no marker is unknown, not proven accessible.
2Marker letters carry meaning without colour: ! Unverified · V HumanVerified · ? Disputed · X Rejected · square C camera evidence.
3Toggle Coverage to see the grid: grey hatched C = insufficient evidence, amber B = obstacle evidence, green A = evidence present. Click a cell to zoom and filter.
4Use my location recentres the map. Denying permission leaves manual panning fully usable.

2.2 Report an obstacle (/report/new or + Report)

1Fill Title (name the place), Obstacle type (BlockedSidewalk · BrokenSurface · MissingOrBlockedRamp · StairsOrStep · ConstructionBarrier · Other · Unknown), Severity (Unknown · Low · Medium · High).
2Location: Use my location (GPS + accuracy note; over 50 m warns to drag the pin), Pick on map, or type coordinates. Coordinates are a claim, not a verified fact.
3What did you actually see? — Stairs? Ramp? Surface? Leave Unknown when you did not check. A wrong No is worse than an honest Unknown.
4Tick consent, press Create report. The report arrives Unverified — correct and shown openly.

2.3 Photo + Meta AI (report page → Photo evidence)

1Upload JPEG/PNG/WebP ≤ 10 MB (compressed on device, EXIF stripped). Press Run analysis.
2Read the card: ✓ Live Meta AI — provider Meta · muse-spark-1.3 (a Demo/mock badge means pipeline test only), possible obstacle, confidence bar (red <40 · orange 40–70 · green >70), visible evidence, limitations, and Human review required.
3Obstruction share (sam-3.1): a share of the walkway in the photo, never metres, no confidence score. Not measured means unknown — e.g. BrokenSurface is deliberately never measured as a share.

2.4 Compare over time (report page → Evidence explorer)

1Upload a second photo of the same place and analyse both. Pick earlier + later, press Compare photos.
2Four outcomes only, always with explanation: LikelyStillPresent · NotObservedInNewImage · ConflictingEvidence · Inconclusive. Not observed never means removed.

2.5 Quick feedback + correction

1On any report, tap Still visible · Not in new photo · Information wrong or old · Not sure. A tap creates a review note — it never auto-verifies.
2Correct your own claim anytime at /reports/{id}/edit (no login).

2.6 Plan a route (/routes)

1Enter start + destination (type, address search, or click origin/destination on the map), set preferences (Avoid stairs · Verified · Avoid stale · Shortest), press Plan routes.
2Compare 2–3 real OSRM foot-geometry cards ranked by fewest known obstacles: known obstacles within 50 m, unknown % (no report nearby — never clear), Certain vs Uncertain split, stale >30d flag, hasConfirmedStairs warning.
OSRM foot routing is not wheelchair-validated. No route is ever labelled wheelchair-safe. Recommended means fewest proven obstacles — not proven safe. Preferences reorder; they never hide an obstacle.

3. Reviewer console (/reviewer) — Reviewer login

1Open Reviewer dashboard, press Sign in on the Reviewer card (one tap). The User card is there so you can prove a plain user gets 403.
2Reports waiting for review — unverified reports, camera candidates, duplicate suggestions, conflicting comparisons. Open a report, read photo + AI + timeline.
3Decide with a note: HumanVerified (seen and true) · Disputed (evidence disagrees) · Rejected (no evidence / invalid). The decision is stored beside the AI outcome — never overwrites it. Duplicates: Confirm (pointer, stays visible) or Reject (stays independent).
4Check Recent audit trail — actor, previous to new, note, time. The queue reloads after every decision. Log out from the session bar when done.
An Admin login also passes this queue. A User login is rejected with Your session is not a reviewer session — expected behaviour, not a bug.

4. Admin console (/admin) — Admin login only

1Sign in with the Admin card (one tap). Reviewer/User sessions see Admin-only — the API answers 403 and must sign out first.
2Camera registry — Register camera (provider, external id, label, city, lat/lon, feed URL, cadence 60s+, permission note). A camera cannot be enabled without a permission note. Poll now pulls one live frame: unchanged creates nothing (no AI cost); changed becomes CameraFeed evidence on the nearest report within 100 m, or a new auto CameraDetected candidate (Unknown, Unverified) entering the same Meta AI queue. Square C on the map is evidence, never a verdict. Auto-polling is OFF on the demo — trigger manually. Stale (10 min+ without success) is flagged, never trusted.
3City analytics — total reports, human-verified percent, stale percent, unknown share, wrong/stale feedback, 7-day chart. Live from GET /api/admin/stats.
4Reputation — Bronze 1+ · Silver 3+ · Gold 5+ verified reports. Empty on the demo because seeded reports have no signed-in author — shown as empty, not invented.
An admin never edits a verdict from here. Verification happens only in /reviewer.

5. Honesty rules — read before a real trip

You seeIt means
No reports / empty mapNobody reported here — unknown, not clear.
NotObservedInNewImageNot seen in the newer photo — never proves removed.
Unknown / not measuredNot checked — never estimated, never 0%.
Route card RecommendedFewest known obstacles — not wheelchair-safe proof.
Camera frame (highway)Traffic view, not footpath — stays Inconclusive by design.
