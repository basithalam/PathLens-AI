PART C — How a reviewer reviews (Reviewer login)

Screen: /reviewer → Reviewer dashboard (Human review turns a claim into something others can rely on… previous value is never erased). Sign in with the one-tap Reviewer card (reviewer@pathlens.local / Reviewer@123). The User card exists to prove 403; a User session sees Your session is not a reviewer session. Log in with a reviewer account. An Admin login also passes the queue.

C1. Work the queue top to bottom

Reports waiting for review (N) — every card: title link (Open →), chips (obstacle · Unverified · created date · Camera candidate / Possible duplicate of XXXXXXXX). Open the report, read photo + AI findings + timeline, come back, type a Review note (placeholder e.g. Verified on site today, ramp clear), press HumanVerified (green) / Disputed (ghost) / Rejected (red). Result line: Marked HumanVerified — audit recorded or Review failed (400/401/403): …. Decide each row — one shared note box is per-card state, not global.

Stale cameras (N) — No enabled camera is stale right now vs stale cards (provider · city · last success · error, red Stale, Do not treat this feed as current evidence). Read-only here; polling lives in /admin.

Comparisons waiting for review (N) — card: comparison → report link · Inconclusive · created, same three buttons + note.

Possible duplicates: two buttons per card — Confirm duplicate (now a pointer to the main report; nothing was deleted) / Reject duplicate (both reports stay independent). No suggestion = reviewer decides on the report itself.

C2. Check the audit + log out

Recent audit trail (N) — rows: time, entity · action, from → to + id prefix, note. Empty: No review actions recorded yet. Rule to remember: a review is stored beside the AI outcome (effective outcome changes, original never overwritten). Log out from the session bar pill when done.
