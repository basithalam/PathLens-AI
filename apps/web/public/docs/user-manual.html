2. Public user — no account needed

2.1 Accessibility map (/map)

1Open Accessibility map. Pan or zoom — reports reload for the area you look at. A place with no marker is unknown, not proven accessible.
2Marker letters carry meaning without colour: ! Unverified · V HumanVerified · ? Disputed · X Rejected · square C camera evidence.
3Toggle Coverage to see the grid: grey hatched C = insufficient evidence, amber B = obstacle evidence, green A = evidence present. Click a cell to zoom and filter.
4Use my location recentres the map. Denying permission leaves manual panning fully usable.

2.2 Report an obstacle (/report/new or + Report)

1Fill Title (name the place), Obstacle type (BlockedSidewalk · BrokenSurface · MissingOrBlockedRamp · StairsOrStep · ConstructionBarrier · Other · Unknown), Severity (Unknown · Low · Medium · High).
2Location: Use my location (GPS + accuracy note; over 50 m warns to drag the pin), Pick on map, or type coordinates. Coordinates are a claim, not a verified fact.
3What did you actually see? — Stairs? Ramp? Surface? Leave Unknown when you did not check. A wrong No is worse than an honest Unknown.
4Tick consent, press Create report. The report arrives Unverified — correct and shown openly.

2.3 Photo + Meta AI (report page → Photo evidence)

1Upload JPEG/PNG/WebP ≤ 10 MB (compressed on device, EXIF stripped). Press Run analysis.
2Read the card: ✓ Live Meta AI — provider Meta · muse-spark-1.3 (a Demo/mock badge means pipeline test only), possible obstacle, confidence bar (red <40 · orange 40–70 · green >70), visible evidence, limitations, and Human review required.
3Obstruction share (sam-3.1): a share of the walkway in the photo, never metres, no confidence score. Not measured means unknown — e.g. BrokenSurface is deliberately never measured as a share.

2.4 Compare over time (report page → Evidence explorer)

1Upload a second photo of the same place and analyse both. Pick earlier + later, press Compare photos.
2Four outcomes only, always with explanation: LikelyStillPresent · NotObservedInNewImage · ConflictingEvidence · Inconclusive. Not observed never means removed.

2.5 Quick feedback + correction

1On any report, tap Still visible · Not in new photo · Information wrong or old · Not sure. A tap creates a review note — it never auto-verifies.
2Correct your own claim anytime at /reports/{id}/edit (no login).

2.6 Plan a route (/routes)

1Enter start + destination (type, address search, or click origin/destination on the map), set preferences (Avoid stairs · Verified · Avoid stale · Shortest), press Plan routes.
2Compare 2–3 real OSRM foot-geometry cards ranked by fewest known obstacles: known obstacles within 50 m, unknown % (no report nearby — never clear), Certain vs Uncertain split, stale >30d flag, hasConfirmedStairs warning.
OSRM foot routing is not wheelchair-validated. No route is ever labelled wheelchair-safe. Recommended means fewest proven obstacles — not proven safe. Preferences reorder; they never hide an obstacle.

3. Reviewer console (/reviewer) — Reviewer login

1Open Reviewer dashboard, press Sign in on the Reviewer card (one tap). The User card is there so you can prove a plain user gets 403.
2Reports waiting for review — unverified reports, camera candidates, duplicate suggestions, conflicting comparisons. Open a report, read photo + AI + timeline.
3Decide with a note: HumanVerified (seen and true) · Disputed (evidence disagrees) · Rejected (no evidence / invalid). The decision is stored beside the AI outcome — never overwrites it. Duplicates: Confirm (pointer, stays visible) or Reject (stays independent).
4Check Recent audit trail — actor, previous to new, note, time. The queue reloads after every decision. Log out from the session bar when done.
An Admin login also passes this queue. A User login is rejected with Your session is not a reviewer session — expected behaviour, not a bug.

4. Admin console (/admin) — Admin login only

1Sign in with the Admin card (one tap). Reviewer/User sessions see Admin-only — the API answers 403 and must sign out first.
2Camera registry — Register camera (provider, external id, label, city, lat/lon, feed URL, cadence 60s+, permission note). A camera cannot be enabled without a permission note. Poll now pulls one live frame: unchanged creates nothing (no AI cost); changed becomes CameraFeed evidence on the nearest report within 100 m, or a new auto CameraDetected candidate (Unknown, Unverified) entering the same Meta AI queue. Square C on the map is evidence, never a verdict. Auto-polling is OFF on the demo — trigger manually. Stale (10 min+ without success) is flagged, never trusted.
3City analytics — total reports, human-verified percent, stale percent, unknown share, wrong/stale feedback, 7-day chart. Live from GET /api/admin/stats.
4Reputation — Bronze 1+ · Silver 3+ · Gold 5+ verified reports. Empty on the demo because seeded reports have no signed-in author — shown as empty, not invented.
An admin never edits a verdict from here. Verification happens only in /reviewer.

5. Honesty rules — read before a real trip

You seeIt means
No reports / empty mapNobody reported here — unknown, not clear.
NotObservedInNewImageNot seen in the newer photo — never proves removed.
Unknown / not measuredNot checked — never estimated, never 0%.
Route card RecommendedFewest known obstacles — not wheelchair-safe proof.
Camera frame (highway)Traffic view, not footpath — stays Inconclusive by design.
